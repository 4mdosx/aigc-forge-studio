# 图库检索质量设计

日期 2026-11-22。对象：`/capture` 的「找相似」与「自动分组」。
基线：`style-embedder-v4`（DINOv3-H CLS → MLP → 7 维）。

## 一句话

瓶颈不在索引、不在算力、不在分辨率，**在向量本身**：7 维 head 把 DINO 的 1280 维压到 7 维，丢掉了风格信息。换回裸 CLS 后检索质量是原来的 2.2 倍（内容）、3.7 倍（风格），同时必须换聚类算法——现有的 average-linkage 在 1280 维下会退化成一个巨型簇。

## 判据

两套真值，都不需要人工标注：

- **内容相关性**：WD14 tag 的 Jaccard。同角色/同场景 → 高。
- **风格相关性**：`source_url` 相同（同一 pixiv 作品）→ 视为同风格。1824 张来自 358 个作品，平均 5.09 张/簇，随机命中率 3.0%。

指标取查询图的 top-k 邻居与真值的平均重合，再除以随机基线得到 lift。

## 实测

### 检索（top-10）

| 向量 | 维度 | tagJ@10 | 同源@10 |
|---|---|---|---|
| head7（现状） | 7 | 0.148（1.49x） | 0.160（5.3x） |
| DINO CLS @224 | 1280 | 0.328（**3.30x**） | 0.588（**19.6x**） |
| DINO CLS @448 | 1280 | 0.329（3.31x） | 0.586（19.6x） |
| CLS @224 + PCA 白化 256 | 256 | 0.323（3.26x） | 0.598（20.0x） |

两个结论：

1. **分辨率不是瓶颈。** 224 和 448 打平，448 贵 2.2 倍。可以用 224，单张 107ms，全量 1824 张约 4 分钟。现状用 bucket 原尺寸（832×1216）跑 head，单张 3.6s，全量 109 分钟——纯浪费。
2. **别降维。** 白化 256 与 1280 持平，但 1280 的检索成本已经低到不用优化：全表余弦 6ms，存储 f16 只要 2.5KB/图（全库 4.7MB）。降维只增加一层版本耦合。

人工抽查确认（4 组查询，head7 vs CLS 各取 top-8）：head7 的邻居经常内容勉强对、画风全不搭；CLS 的邻居成片同画风、同配色。机甲立绘那组差距最直观——head7 返回了写实裸体、蓝色精灵、红色和服，CLS 返回 8 张同类机娘立绘。

### 分组（k=6）

| 方案 | 同源对召回 | 组规模 |
|---|---|---|
| 随机基线 | 0.167 | — |
| head7 + average-linkage 二分 | 0.572 | 824 / 505 / 432 / 35 / 24 / 4 |
| CLS + kmeans（cosine） | 0.720 | 675 / 459 / 259 / 198 / 146 / 87 |
| CLS + ward（L2 归一化后欧氏） | **0.878** | 661 / 418 / 376 / 194 / 102 / 73 |

坑在这里：**换向量必须同时换聚类算法**。7 维下能用的二分策略搬到 1280 维会崩——一个簇吃掉 1816 张，剩下全是 1~3 张的离群点。原因是高维余弦的集中效应，average-linkage 找不到有意义的切点。kmeans 和 ward 都正常，ward 更好（0.878 vs 0.720，tag 相近对同组率 0.977 vs 0.855）。

k 越大召回越低（k=10 → 0.731，k=16 → 0.491），这是必然的。实用区间 k=8~12，1824 张时每组 150~250 张。

### 稳定性

抽掉 10% 的图重算，剩余图的 ARI：k=6/10/16 都是 **0.55~0.58**。

也就是说**每次重算分组，有一半的边界会变**。「图片多了分类效果差」的感受，一半来自这个——不是分得更差，是分得不一样，人接不上上次的整理。这跟维度无关，是层次/质心聚类天生全局依赖。

推论：**分组结果必须落库**，当资产处理，不做成每次查询的副产品。

### 多样性

CLS 的 top-10 里同源图占 58%，平均只有 3.7 个不同作品。找素材时这是冗余。

MMR 实测（λ 为相关性权重）：

| λ | 同源@10 | top-10 中不同作品数 |
|---|---|---|
| 1.0（纯余弦） | 0.586 | 3.7 |
| 0.85 | 0.584 | 4.2 |
| 0.7 | 0.570 | **4.6** |
| 0.5 | 0.440 | 5.9 |

λ=0.7 几乎不掉相关性，作品数涨 24%。做成可选开关，默认 1.0。

## 架构

### 向量层

- 模型 `dinov3-cls-224-v1`：DINOv3-ViT-H/16+ 的 CLS，输入 `processed.png` 直接 resize 224（方形拉伸，跟 DINO 训练前置一致，不做白边）。
- 存 float16，2.5KB/图。**新表 `image_vectors(asset_id, model_version, dim, vec BLOB)`**，不塞进 `image_assets.embedding_json`——1280 个数字写成 JSON 是 10KB/行的文本，全表 SELECT 一次要解析十几 MB，而现在这个查询每次检索都会跑。
- 版本守卫沿用现有机制：`modelVersion` + 维度不一致直接拒。

### 检索层

- 内存矩阵（numpy float32）+ `argpartition`。1824 张 6ms，2 万张约 0.7s。
- 上 HNSW 的阈值定在 **5 万张**，之前暴力够用，别提前引入依赖。
- 同源去重与 MMR 都在 `argpartition` 之后做，只处理 top-k×3 的候选，开销可忽略。

### 分组层

- **ward on L2-normalized CLS**，O(n²) 内存，2 万张约 3GB——超过 2 万张要先 kmeans 粗分（k≈n/500）再组内 ward。
- 结果落库：`group_plans(id, created_at, k, model_version, params_json)` + `group_members(plan_id, asset_id, group_no)`。
- 新图默认进「未分组」池，用最近质心挂靠（实测与全量结果一致率 0.80，够用；漂了就让用户手动改）。
- 重算分组是显式动作，会生成新 plan，旧 plan 保留可回滚。

## 迁移

1. critic 加 `/embed?mode=cls`，或直接改 `embed()` 返回 CLS——用 `modelVersion` 区分，不给老版本留分支。
2. 建 `image_vectors` 表，写一次性回填脚本（224 + bs16，4 分钟）。
3. `EMBEDDING_MODEL` 改 `dinov3-cls-224-v1`，跑 `POST /capture/embeddings/rebuild` 触发重算。上一轮已经打通「定稿图也能补 embed」的路径。
4. 分组 API 加 `balance` 之外的 `algorithm` 参数（`ward` / `kmeans`），默认 ward；落库逻辑另起一步。

## 验收

- `tagJ@10 ≥ 0.30`、`同源@10 ≥ 0.55`（现在 0.148 / 0.160）。
- k=6 同源对召回 ≥ 0.85。
- 全量重算 < 10 分钟，单次检索 < 50ms。
- 人工抽查 4 组，CLS 的 top-8 至少 6 张画风一致。

## 实施状态（2026-11-22）

已落地：

- `critic/embed.py` 默认输出 1280 维 CLS（`mode=cls`），7 维头保留为 `mode=head` 对照。
  预处理走 `square_array`：方形缩放到 224，不补白边。
- 新表 `image_vectors(asset_id, model_version, dim, vec BLOB)`，f32 二进制 5KB/图。
  `runner/src/capture/vectors.ts` 负责编解码与读写；`image_assets.embedding_json`
  不再写入向量，列表查询也彻底不碰它。
- `EMBEDDING_MODEL = dinov3-cls-224-v1`，版本守卫沿用：critic 缓存记 modelVersion + 维度，
  不一致直接 400；nearest 命中旧版本向量返回 409；分组把旧版本图记进 `stale`。
- 分组改成 ward（`_cluster_chunks`），`balance=even` 保留。实测 316 张真实数据
  k=4 得 [130, 76, 56, 54]，k=6 得 [95, 76, 56, 35, 35, 19]。
- 分组结果落库：`group_plans` + `image_groups`，API 是 `GET/PUT/DELETE /capture/groups`
  与 `POST /capture/groups/assign`（新图挂最近质心）。前端进页面自动读回，
  「重置」会一起清库。

未做：

- MMR 多样化开关（λ=0.7 的实测数据在上面，接口没接）。
- 5 万张以上的 HNSW 索引。
- mean-patch / 多层特征拼接。

## 不做

- **mean-patch / 多层特征拼接**：可能再涨，但得重跑两遍模型，收益未验证，等有闲。
- **PCA 降维**：6ms 已经不疼，降维只换来版本耦合。
- **文本检索 tag→图**：需要 CLIP 类模型，另一条线。
